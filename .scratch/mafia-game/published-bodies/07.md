## What to build

Living Players can exchange public Meeting messages, living Mafia can coordinate in a private Night channel, and each Player can recover only the history they are entitled to read.

Each slice includes its relevant server behavior, explicit protocol contract, client UI/state, documentation, and tests. Preserve per-Room serialization, bounded asynchronous delivery, strict decoding, and frame-boundary application. Use the approved WebSocket behavior seam, focused frontend tests, and browser verification; do not defer privacy or recovery of this slice's own state to a later ticket.

## Acceptance criteria

- [ ] Provide public text chat during Meeting discussion and voting, and private Mafia text chat only to living Mafia during Night.
- [ ] Enforce Room, phase, and living/Role permissions on the server. Render messages as text rather than executable markup.
- [ ] Eliminated Players can read public Meeting discussion but cannot send chat. An eliminated Mafia retains previously received Mafia messages and receives no later Mafia messages.
- [ ] Preserve public Meeting history and each recipient's authorized private history for the Game and restore it on Reconnect without leaking another Player's private history.
- [ ] Confine messages to the current Room and Game. Provide no voice, ghost chat, extra direct-message channels, or Mafia chat outside Night.
- [ ] Use bounded non-blocking delivery without coalescing chat as movement. A slow or reconnecting client receives only authorized history through the existing recovery behavior.
- [ ] Verify actual per-recipient payload streams across public/private phases, recovery, another Room, and a Mafia eliminated through Meeting voting. Check client frame-boundary rendering and text handling.
- [ ] Demonstrate chat from living Village, living Mafia, and eliminated perspectives. Update the protocol and run full affected checks.
