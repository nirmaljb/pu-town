## What to build

Players see the complete timed Night-to-Meeting cycle without a moderator. With no actions submitted, Nights announce no death and Meetings announce no elimination, then another Night begins.

Each slice includes its relevant server behavior, explicit protocol contract, client UI/state, documentation, and tests. Preserve per-Room serialization, bounded asynchronous delivery, strict decoding, and frame-boundary application. Use the approved WebSocket behavior seam, focused frontend tests, and browser verification; do not defer privacy or recovery of this slice's own state to a later ticket.

## Acceptance criteria

- [ ] Run 90-second Night, 6-second Night outcome, 120-second discussion, 30-second voting, and 6-second voting result in order, repeating from Night.
- [ ] Display server-owned phase and countdown, sleep presentation, and outcome screens while keeping Players seated.
- [ ] Advance without client frames, tab focus, Host connectivity, or incoming Player actions. Do not add pause, phase-skip, restart, or early-completion controls.
- [ ] No submitted actions produces no death and no elimination. This is a demoable timed cycle; later tickets add action outcomes without replacing the phase lifecycle.
- [ ] Give actions an unambiguous round/phase context so a delayed request cannot become a choice for a later phase.
- [ ] Serialize deadline transitions with Room operations and publish each transition consistently through bounded outbound delivery and the existing client frame boundary.
- [ ] Recover directly into the current phase and deadline, including after crossing several boundaries while disconnected; do not restart timers or replay expired phases.
- [ ] Use controlled-clock handler tests and focused frontend tests to cover boundaries, repeated scheduling, suspended clients, recovery, and Seat continuity. Demonstrate the cycle in the browser and run the full affected checks.
