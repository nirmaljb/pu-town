## What to build

The assembled Game ends automatically when a faction wins, shows every original Player's Role on a persistent result screen, and is verified as a complete ten-Player experience.

Each slice includes its relevant server behavior, explicit protocol contract, client UI/state, documentation, and tests. Preserve per-Room serialization, bounded asynchronous delivery, strict decoding, and frame-boundary application. Use the approved WebSocket behavior seam, focused frontend tests, and browser verification; do not defer privacy or recovery of this slice's own state to a later ticket.

## Acceptance criteria

- [ ] Check victory after simultaneous Night resolution, Meeting elimination, and Forfeit. Zero living Mafia means Village wins; otherwise living Mafia at least equal to living Village means Mafia wins.
- [ ] End the contest on victory, stop further gameplay actions and phase cycling, and keep the result stable through subsequent departures or recovery.
- [ ] Reveal every original Player's Role, including eliminated and forfeited participants, and show the winning Faction on a result screen.
- [ ] Keep final results available while the Room exists. Do not add rematch, restart, or Lobby reset; another Game requires a new Room. Preserve recovery and final-membership Room removal.
- [ ] Test both wins reached through gameplay and through Forfeit, last-death/last-vote timing, no premature victory before Night resolution completes, full-roster disclosure, and recovery into results through the main protocol seam.
- [ ] Run a complete ten-client browser Game with a healthy backend and supported client port. Exercise Role reveal, private/public chat, every Night Role, immutable confirmations, Meeting votes, spectator views, recovery, and final results; inspect unauthorized clients for data leakage.
- [ ] Verify the assembled behavior follows all acceptance rules in parent #12. Every preceding slice already owns its own tests; add only meaningful cross-feature coverage and fix integration issues here.
- [ ] Update the human-facing workflow and operational guidance to the complete Game, run both full component suites plus frontend typecheck/build, and run backend packaging if startup/scheduling changed. Report automated and browser checks separately.
